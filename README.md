# Chat GPT with GitHub

An independent workshop for exploring ideas, building software, and documenting experiments through human–AI collaboration.

This repository is intentionally technology-agnostic. Its purpose is not to host one predetermined application, but to give promising ideas room to become real projects.

## Mission

Use this space to:

- Explore ideas that are technically interesting and worth building.
- Prototype unfamiliar technologies and evaluate them through working software.
- Develop substantial projects from concept to usable releases.
- Preserve research, decisions, experiments, and lessons learned.
- Prefer useful, maintainable results over demos that stop at the first milestone.

## Working principles

1. **Start with the problem.** Choose a technology only after understanding what the project needs.
2. **Build, don't just brainstorm.** Ideas should progress towards prototypes, tests, documentation, and releases.
3. **Keep experiments honest.** Record assumptions, limitations, results, and reasons for abandoning an approach.
4. **Keep the repository understandable.** Give each project a clear scope, structure, and README.
5. **Protect existing work.** Inspect before changing; avoid destructive changes and keep meaningful history.
6. **Be ambitious, but incremental.** Work in small, verifiable steps that can grow into larger systems.
7. **Make decisions explicit.** Record important architectural and product decisions so future work has context.

## How work is organized

The repository may contain several independent projects and experiments. A project should earn a permanent place here by demonstrating a clear purpose and a credible path to completion.

A lightweight structure will emerge as the work grows. We will avoid creating empty folders or imposing a complex monorepo architecture before there is a real need.

## Project lifecycle

A typical project moves through these stages:

1. **Discovery** — define the problem, users, constraints, and alternatives.
2. **Validation** — test the riskiest assumptions with research or a small prototype.
3. **MVP** — build the smallest complete and genuinely useful version.
4. **Iteration** — improve reliability, usability, performance, and scope based on evidence.
5. **Release** — document installation, usage, limitations, and version history.

Not every experiment needs to become a product. A well-documented conclusion that an approach does not work is also valuable.

## Collaboration

The human contributor sets goals, provides feedback, and approves consequential decisions. The AI collaborator is expected to contribute ideas, research, implementation, reviews, documentation, and initiative—not merely wait for line-by-line instructions.

Changes should be transparent, reviewable, and connected to a clear purpose.
